version1.0 默认回滚版本说明

一、版本定位

这个版本以提交 a33d54035faf86deef3d9f401b52121d52d3a19a 为基线。

它可以作为后续继续扩展的默认回滚版本，原因是：

1. 默认首轮视频关闭
2. 默认主要走大模型文字回复
3. 地址、价格、预约这类规则回复没有像后续版本那样大范围强插图片
4. 整体表现比后续多个测试版本更干净，更适合作为稳定起点


二、为什么它不是“绝对纯净的 LLM 回复版本”

这个版本看起来已经比较干净，但它仍然不是“所有用户消息都百分百原样走大模型文字回复”的版本，原因有三类：

1. 有些输入会直接走固定回复

- 用户如果直接提交手机号，会直接回复固定承接话术
- 这类回复不是大模型现场生成的，而是系统预设好的

2. 大模型生成出来的话，不一定原样发出去

- 如果回复里碰到联系方式相关的敏感表达，系统可能会改成更收口的固定说法
- 如果回复里碰到地址、价格等受限制内容，也可能被改写
- 如果大模型请求失败，会直接改成系统自己的兜底话术

3. 文本发出去后，仍然可能补发图片

- 这版默认不主动走首轮视频
- 但图片逻辑没有彻底关闭
- 某些场景下，系统会在文字发完以后，再补发联系方式图片


三、哪些场景会走固定回复

当前确认会走固定回复或固定兜底的场景有：

1. 用户直接发手机号
- 系统直接承接联系方式

2. 大模型失败
- 系统会换成固定兜底话术，不再使用大模型原始回复

3. 大模型回复里碰到联系方式风险
- 例如带出电话、微信、联系方式等容易越界的表达时，系统会改成更安全的固定说法

4. 大模型回复里碰到地址或价格风险
- 如果内容触发系统限制，也可能被系统改写，不是原样发出


四、什么情况下会发图

这个版本不会默认首轮发视频，但图片仍然会在以下场景出现：

1. 用户直接问怎么联系、怎么加、联系方式、微信、电话、二维码这类问题
- 文字发完后，可能补发一张联系方式图片

2. 前文已经聊到地址后，用户继续追问“具体位置”“更详细位置”这类内容
- 文字发完后，可能补发联系方式图片
- 注意：这里补发的不是地址图，而是联系方式图片

3. 大模型失败后
- 系统用了兜底话术后，可能继续补发联系方式图片


五、关于地址路由的实际表现

这个版本并不是“完全不识别地址”。

像“五角场”这种地名，系统仍然能识别到对应门店方向。

但它通常不会像后续某些版本那样，让地址规则强行接管整轮回复。实际表现更接近：

1. 系统识别到了地名和门店方向
2. 最终仍以大模型文字回复为主
3. 不会默认改成强规则地址回复

所以这版的特点不是“地址识别关闭”，而是“地址识别还在，但地址规则接管变弱了”。


六、结论

version1.0 适合作为默认回滚版本。

原因不是它足够纯，而是它足够稳、足够干净、干预比后续版本少。

但如果后面要继续做“绝对纯净版本”测试，仍然需要额外处理下面三件事：

1. 去掉手机号直接固定承接
2. 去掉联系方式、地址、价格相关的固定改写
3. 去掉文字发送后的补图逻辑
